## 6. Failure Cases

The main observed failure was OCR noise. The rerun produced distorted Arabic words, especially names and place names: the sister name and Yaqub destination were not cleanly recognized, and the model answered the destination with the literal noisy form shown in the retrieved OCR. This caused a partially correct result rather than a reliable factual answer. The eye-operation question also had only a fragmentary OCR reference, so the answer could not safely identify the exact procedure.

Retrieval usually placed the matching indexed page first, but the selected five-chunk context often mixed that page with chunks from other pages, including unrelated `AF_*` records or other letters. This is context contamination rather than a missed target in these ten runs. The final question exposed a semantic attribution error: the retrieved text contained the name Marie Joseph Gharib, but the answer assigned the thanks to the wrong person.

## 7. Mitigation

The existing implementation mitigates these risks through document preprocessing, Kraken line segmentation with the Muharaf-trained model, human-reviewable raw OCR, Chroma semantic retrieval combined with an Arabic BM25-style lexical index and RapidFuzz recovery, source/page/chunk metadata, and page-aware context selection. The Groq system prompt restricts answers to retrieved context, asks for uncertainty when OCR is unclear, and prohibits invented names, places, dates, or events. These mitigations were observed in the code and were not changed for this evaluation. Human OCR correction remains necessary for ambiguous names, places, and numbers.

## 8. Conclusion

On this ten-question run, the production pipeline retrieved a relevant indexed page for every question, and no response was classified as fully hallucinated. However, noisy OCR and mixed-page context reduced reliability: six answers were fully correct, three were partially correct, and one was incorrect. The system is useful for assisted exploration, but the saved OCR and answer should be human-verified before being treated as authoritative.

## Reproducibility

Run `python -m scripts.evaluate_validation` from the project root. It discovers the five validation images, executes the existing OCR and hybrid RAG functions, and regenerates `docs/evaluation_results.csv` and `docs/evaluation_raw.json`. A Groq API rate limit can prevent a fresh generation run; the captured raw file is the source for this report.
